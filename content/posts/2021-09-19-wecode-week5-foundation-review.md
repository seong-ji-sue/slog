## ✅ 배운 것 / 한 것

이번 주에 배운 것들이다.

- 백엔드·프론트엔드를 종합적으로 초기세팅할 때 무엇을 해야 하는지
- Express를 효율적으로 쓰는 방법
- MVC 모델을 쓰는 이유
- Route, Controller, Service, Server, Model(DAO)에 어떤 코드를 담아야 하는지
- `require` 대신 `import` 구문으로 모듈을 가져오는 방법
- Prisma 사용법과 ORM 활용
- 터미널에서 테이블을 생성하고 문법을 쓰는 방법
- `fetch`와 비동기 함수 사용법
- 프론트엔드가 요청한 부분을 백엔드 단에서 처리하는 방법
- `await`, `async` 사용법

리액트 미션은 다음과 같은 순서로 진행했다.

1. 커피 리스트 및 상세 정보 API
2. 스타벅스 데이터베이스 구축
3. ES6 syntax 사용
4. Prisma를 활용한 데이터베이스 구축
5. CRUD — Create & Read
6. Layered Pattern 구현
7. 암호화
8. JWT 발행
9. CRUD — Create & Delete(음료 Like 기능)
10. CRUD — comments or reviews

알게 된 것도 몇 가지 정리했다.

- 우분투는 터미널 상에서 모든 걸 설치한다
- 테이블을 만들기 전에 먼저 관계를 그려보고 생각한다
- 백엔드가 서버로부터 데이터를 보내주면 프론트엔드가 요청·응답을 처리한다
- 데이터에서도 변수 중복을 피하는 게 좋다
- 칼럼을 추가할 땐 `INSERT INTO`를 터미널에 바로 치기보다 메모장에 정리한 뒤 적용하는 게 낫다

## ✅ 질문과 답변

- **질문**: model 단에는 SQL 문만 넣어서 처리하도록 생각했는데, ORM을 쓰면 model 단이 여전히 필요한가?
  **답변**: model 단에서 SQL 문을 처리하는 게 맞다. `async` 자체를 model 단에 넣으면 ORM도 함께 쓸 수 있다.
- **질문**: 라우터 단은 경로 분기만 하는 게 좋은가, 아니면 유효성 검사까지 하는 게 좋은가?
  **답변**: 경로 분기만 하고 나머지는 Controller에서 처리하는 게 낫다.
- **질문**: 미들웨어에서 권한을 알려준다고 했고 서비스 단에서 권한에 따라 실행 함수를 정한다고 했는데, 그 권한 여부는 서비스 단에서 import해서 가져와야 하는가?
  **답변**: 미들웨어에서 `req`, `res`를 받을 수 있다. `req` 헤더에서 추출한 뒤 `req`에 값을 넣어주면 Controller가 가져가서 서비스로 넘겨서 쓴다.

몰랐던 용어도 따로 정리해뒀다 — `nest.js`, 콜스택, 실행 컨텍스트, 제너레이터, ECMAScript 등. 각각 개별 URL로 찾아 공부했다.

## ✅ 배운 점 / 아쉬운 점

**잘한 점**

- 프론트엔드는 개념보다 코드를 먼저 쓰고 공식 문서를 보며 오류를 고쳐가는 방식으로 익혔는데, 백엔드는 반대로 개념을 어느 정도 잡고 가야 코딩이 된다는 걸 깨달은 것 — 서버와 DB를 구동해야 하고 낯선 문법이 계속 나오기 때문이다
- Java에서 MVC 모델을 해본 경험이 있어서 구조 자체는 낯설지 않았던 것

**아쉬운 점**

- SQL과 자바스크립트 중급 수준을 미리 끝내놓지 않은 것 — 미리 해뒀으면 이번 주가 덜 힘들었을 것 같다
- 프로젝트를 앞두고 초기세팅 방법을 미리 정리해두지 않아서 이번 주에 급하게 정리한 것

추석 연휴가 한 주 껴 있어서 그나마 다행이었다. 다음 프로젝트 때는 이번에 정리한 초기세팅 가이드를 그대로 적용해볼 생각이다.
