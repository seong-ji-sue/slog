## 7. 자동 포스팅 스킬 설계 (요구사항 1)

**이름**: `blog-draft` (slog 레포 `.claude/skills/blog-draft/SKILL.md`)

**동작 흐름**:
```
사용자가 작업 후 /blog-draft 호출 (인자: 없으면 현재 세션 전체)
  1. 세션에서 한 작업을 의미 단위로 요약 (목표/내역/의사결정/막힌 것/결과)
  2. templates/worklog.md 구조 + STYLE_GUIDE.md 말투 적용해 초안 생성
  3. 시크릿·회사명·내부 URL 자동 마스킹 스캔 (grep 패턴)
  4. content/drafts/YYYY-MM-DD-slug.md 저장 (draft: true 고정)
  5. 사용자 검토 → draft: false + published 이동 → git commit
```

**안전 규칙**: 자동 공개 금지(항상 draft), 마스킹 체크리스트 통과 전 publish 불가, 훅으로 publish 시 secret-scan 실행
**확장(선택)**: Stop 훅으로 "오늘 작업 블로그 초안 만들까?" 제안 — Phase 3

## 11. v2 피벗 — 회사·개인 통합 AI 서칭 지식블로그 (2026-07-19)

P2~P4에서 "이직용 포트폴리오"로 시작했으나, 아래처럼 목적을 확장함. 기존 5화면(홈·글목록·글상세·시리즈·소개)과 P4에서 구현한 태그 기능은 유지하고, 이번 피벗은 그 위에 콘텐츠 축·화면·자동화를 추가하는 **확장**이다.

### 11-1. 재정의된 목적

| # | 목적 | 비고 |
|---|------|------|
| 1 | 회사 작업과 개인 작업을 모두 블로그 형식으로 기록 | 이직 어필은 부차 목적으로 유지, 1차 목적은 기록 그 자체 |
| 2 | 과거에 구현·기록한 내용을 나중에 AI(LLM) 서칭으로 쉽게 찾을 수 있게 함 | frontmatter 표준화가 1차 수단. RAG/임베딩 서칭은 P6로 유보 |
| 3 | 사용자가 "스킬"(작업 요약)을 입력하면 템플릿에 맞춰 블로그 글로 자동 작성 | 기존 `blog-draft` 스킬(P3) 확장으로 처리 — 신규 메커니즘 아님 |
| 4 | 게시물마다 태그를 늘려 관리하고, 태그 관계를 그래프(네트워크 시각화) 형태로 볼 수 있게 함 | P4의 `/tags` 리스트 뷰에 더해 홈 화면에 그래프 뷰 추가 |

### 11-2. 콘텐츠 taxonomy — 프로젝트 카테고리 7종

기존 `categories`(딥다이브/트러블슈팅/회고/작업로그)와 별개로, 게시글이 어느 프로젝트에 속하는지 나타내는 `project` frontmatter 필드를 신설한다.

| project 값 | 설명 | 성격 |
|-----------|------|------|
| `유튜브-자막-요약` | 유튜브 자막 다운로드 및 요약 도구 | 개인 |
| `ai-스킬-오케스트레이션` | AI 스킬/에이전트 오케스트레이션 모음 | 개인 |
| `autoit-자동화` | AutoIt 기반 업무 자동화 | 회사 |
| `ssh-key-관리` | SSH Key 관리 솔루션 | 회사 |
| `윈도우-설정` | 윈도우 설정·운영 | 회사 |
| `aws-관리` | AWS 인프라 관리·설정 | 회사 |
| `ai-블로그-자동관리` | 이 블로그 자체의 AI 자동화(spec 파이프라인, blog-draft 등) | 개인 |

### 11-3. 회사 작업 콘텐츠 정책

회사 프로젝트(`autoit-자동화`·`ssh-key-관리`·`윈도우-설정`·`aws-관리`)는 **기술적 구현 내용 위주로 작성**하고, 회사명·내부 시스템명·고객사명·서버 주소 등 식별 정보는 일반화된 설명으로 치환한다(예: "사내 결재 시스템" → "사내 워크플로우 시스템"). 별도의 비공개 게이트 없이 작성 시점에 이 규칙을 적용하는 것을 기본으로 하되, 기존 `blog-draft` 스킬의 secret-scan 훅을 발행 전 마지막 안전장치로 유지한다.

### 11-4. 화면 구조 변경

기존 5화면 구조 유지, 아래 변경만 반영:

- **홈(메인)**: 기존 "전체 글 피드" 목록 뷰에 더해 **그래프 뷰**를 토글로 제공. 그래프 뷰는 태그를 노드로, 같은 글에 함께 쓰인 태그 쌍을 엣지로 표현하는 네트워크 다이어그램(태그 328개 규모 → 인기 태그 클러스터링 또는 포커스 필터링 필요, 상세는 PRD에서 결정)
- **글 상세**: 기존 구조 유지 (변경 없음)
- 참고 레퍼런스: §4의 overreacted.io/joshwcomeau.com/leerob.io 외에, 그래프 뷰는 인기 개발 블로그 중 태그/지식그래프 시각화 사례를 PRD 단계에서 추가 조사

### 11-5. blog-draft 스킬 확장

기존 `.claude/skills/blog-draft/SKILL.md`(P3)에 `project` 필드 선택 입력을 추가해, 스킬 실행 시 7종 프로젝트 카테고리 중 하나를 지정하면 초안 frontmatter에 자동 반영되도록 확장한다. 신규 스킬을 만들지 않고 기존 스킬을 확장한다.

### 11-6. AI 서칭 최적화 — 이번 phase 스코프
