# 회의록 — 태그 인덱스/상세 페이지 추가

- **일시**: 2026-07-19 10:04
- **작업 단위**: 태그(예: Git, Next.js) 클릭 시 해당 게시글 목록을 보여주는 신규 화면 추가
- **참석**: 사용자, 팀장
- **작성**: 팀장

---

## 배경

기존 블로그는 카테고리 필터(/posts)와 시리즈(/series, /series/[name])만 제공. 사용자가 "Git, Next.js 등 글에 해당되는 태그를 뽑아서 항목을 만들고 클릭했을 때 해당 게시글이 나오게" 요청 — 태그 인덱스 + 태그별 상세 페이지 신규 기능.

---

## 주요 논의

> **팀장**: 신규 기능이라 CLAUDE.md 규정상 Gemini 조사 필수 호출 후 진행. Gemini에 Next.js App Router 정적 블로그의 태그 페이지 URL 구조·슬러그 정규화·generateStaticParams 주의점·UX 패턴·SEO를 질의함.

Gemini 조사 요지:
- URL 구조: `/tags`(목록) + `/tags/[tag]`(상세) — 쿼리스트링 방식은 정적 생성과 맞지 않음
- 슬러그: `encodeURIComponent`만으로는 "Next.js" 같은 마침표·공백 포함 태그가 지저분해짐 → kebab-case 정규화(소문자화, 마침표 제거, 공백→하이픈) 권장, 표시명은 원본 태그명 유지하는 slug↔name 매핑 필요
- `generateStaticParams`에서 정규화 없이 원본 태그를 그대로 세그먼트로 쓰면 파일시스템/디코딩 이슈로 매칭이 깨지는 실수가 흔함
- UX: 태그 클라우드보다 count 포함 칩/리스트가 개인 블로그에 흔함
- SEO: 태그 페이지 중복 콘텐츠 이슈는 있으나 현재 규모(태그 328개, 다건 중복)에서는 무시 가능한 수준으로 판단, 별도 noindex 처리는 이번 스코프 제외

실제 데이터 확인 결과 태그 328개 중 마침표 포함은 "Next.js", "Node.js" 2개뿐이라 슬러그 정규화 로직은 단순하게(소문자화 + 마침표 제거 + 공백/특수문자→하이픈) 구현하면 충분하다고 판단.

기존 `/series` 구현(`lib/posts.ts`의 `getSeriesList`/`getSeriesPosts`, `app/series/page.tsx`, `app/series/[name]/page.tsx`)이 동일한 목록+상세 패턴이라 그대로 준용하기로 함.

## 기술 결정

| 결정 항목 | 선택 | 이유 |
|----------|------|------|
| URL 구조 | `/tags`, `/tags/[tag]` | 정적 생성 호환, 기존 `/series` 패턴과 일관 |
| 슬러그 정규화 | `lib/format.ts`에 `tagSlug()` 순수 함수 추가 (소문자화·마침표 제거·공백/특수문자→하이픈) | Gemini 조사 근거, 실데이터에 특수문자 케이스 적음 |
| 데이터 조회 | `lib/posts.ts`에 `getTagsList()`/`getPostsByTag(slug)` 추가 | 기존 `getSeriesList`/`getSeriesPosts`와 동일 패턴 |
