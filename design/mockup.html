다건·단건 파일 전송 구현
— FormData와 multipart 제대로 알기

TL;DR — 파일은 바이너리라 JSON으로 못 보낸다. FormData에 담아 multipart/form-data로 보내야 하고, 단건·다건의 차이는 append 전략에서 갈린다.
1️⃣ FormData2️⃣ multipart/form-data

✅상황 (요구사항)

설계 부장님 : 배포 서버 인증서를 관리자가 UI에서 직접 첨부해야 되고, 플랫폼마다 라이센스 파일들을 업로드할 수 있어야 돼~
백엔드 대리님 : 프론트에서 파일만 전송해주면 쿠버 환경에 주입되게 처리할게요!
예스맨 : YES! 인증서는 단건 + 다른 데이터와 같이, 라이센스는 3개 파일 전송~

일감을 받고 가장 먼저 든 생각은 두 가지였다. '첨부 UI를 어떻게 그리지?' 그리고 '첨부한 파일을 어떤 형태로 보관하고 전송하지?' 평소처럼 Content-Type: application/json으로 보낼 수 없다는 것부터가 출발점이다.

✅File 전용 데이터, Multipart Type

File 인터페이스는 Blob을 상속받는 바이너리 데이터다. 그래서 FormData에 담아 multipart/form-data로 보내야 한다.

// 데이터 저장
formData.append('data', JSON.stringify({ data: data.text }));
formData.append(data.file.type, data.file);

// 출력 — FormData는 콘솔에 바로 안 찍힌다
for (const pair of formData.entries()) {
  console.log(pair[0] + ': ' + pair[1]);
}
이미지 — 요청 본문의 boundary 구분 스크린샷

✅결과 & 배운 점

단건은 데이터와 파일을 한 FormData에, 다건은 같은 key로 여러 번 append. 브라우저가 boundary를 알아서 만들어주니 Content-Type을 직접 지정하지 않는 것이 오히려 정답이었다.
