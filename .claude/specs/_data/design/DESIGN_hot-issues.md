# DESIGN — hot-issues

트렌드 리서치 요약(진행 근거): Gemini CLI는 이 환경에 `GEMINI_API_KEY` 미설정으로 호출 불가 확인 후, Bash 웹 리서치(DuckDuckGo)로 "2026 UI/UX 뉴스 애그리게이터 카드" 관련 실제 아티클 타이틀 목록 확보(이후 요청은 봇 차단) + 기존 지식 종합. 핵심 반영 포인트:
- 뉴스/큐레이션형 카드는 그리드보다 **밀도 높은 리스트형**이 스캔에 유리 — 기존 블로그의 listRow 계열과 궁합이 좋음.
- 출처 뱃지는 텍스트 라벨 필수(색상만으로 구분 금지, a11y).
- AI 요약 콘텐츠는 "AI 요약" 라벨을 명시해 투명성 확보하는 것이 최근 권장 패턴.
- 카드 전체를 링크로 감싼 상태에서 내부에 원문 링크를 중첩하면 중첩 링크(a > a) 접근성 오류가 흔함 — 원문 링크는 상세 페이지에서만 노출(BRIEF Q-03 A안과 일치).
- 스켈레톤은 실제 카드와 동일한 골격(제목·메타 라인 자리)으로 레이아웃 시프트 방지가 표준.

디자인 방향: 기존 "원고지 노트" 에디토리얼 톤을 유지하되, 자체 작성 글(listRow + serif + mark 하이라이트)과 외부 자동수집 콘텐츠(card + sans + 보더 강조)를 시각적으로 분리해 "이건 내가 쓴 글이 아니라 큐레이션"임을 은연중에 전달한다. 사용 토큰: `design_system.json`의 `components.card` / `components.badge.source` / `components.tab.filter` / `components.pagination.pageButton`.

## S-01 핫이슈 피드 목록

- **레이아웃**: 기존 `/posts` 페이지와 동일한 단일 컬럼(`col`, max-width 680px) 구조 유지. 상단에 페이지 타이틀(caption 스타일, 예: "HOT ISSUES") → 검색 입력(`components.input.search`) → 출처 필터 탭(`components.tab.filter`, "전체" + 출처별: Hacker News·GeekNews·Dev.to) → 카드 리스트(`components.card`, 세로 스택 gap 16) → 페이지네이션(`components.pagination.pageButton`, 5페이지 창 이동). 기존 `PostsFilter`와 동일한 인터랙션 골격(검색/탭 변경 시 페이지 1로 리셋)을 그대로 재사용.
- **카드 내부 구성** (한 장당): 상단 라인 = 출처 뱃지(`components.badge.source`, 텍스트 라벨 필수) + 수집일(caption, 상대시간 대신 절대일자 "YYYY.MM.DD" — 기존 `fmtDate`와 통일) 우측 정렬. 중단 = 제목(2줄 말줄임, font_sans 700 — serif·mark는 사용하지 않음: 자체 글과 구분). 하단 = 요약 스니펫 1~2줄(body 톤, muted 컬러) + 좌측 작은 "AI 요약" 캡션 라벨.
- **상태**:
  - 로딩: 카드 3~5개 분량의 스켈레톤(제목 라인 1개 + 메타 라인 1개 + 요약 라인 2개, background를 border색 low-opacity로 채운 블록) — 실제 카드와 동일한 높이·여백으로 레이아웃 시프트 방지.
  - 빈 상태(검색/필터 결과 0건 — REQ-08): 기존 `.no-posts`와 동일 톤의 caption 문구("검색 결과가 없습니다.") + 현재 필터 조건 안내(예: "'{query}' · {출처}") 아래 필터 초기화 텍스트 버튼 제공.
  - 빈 상태(전체 이슈 자체가 0건 — 최초 수집 전/수집 실패 지속 등 A-05 연쇄): "아직 수집된 이슈가 없습니다. 매일 자동으로 갱신됩니다." 문구만 표시, CTA 없음(사용자가 취할 행동이 없으므로).
  - 에러(수집 파이프라인/데이터 조회 실패): 카드 리스트 자리에 inline 에러 블록 — `colors.destructive` 텍스트 + "이슈 목록을 불러오지 못했습니다" + 재시도 버튼. 목록 화면 자체는 SSG/파일 기반이라 조회 실패 가능성은 낮음(A-08) — 주로 클라이언트 네트워크 에러 대비용.
- **흐름**: 진입(REQ-06, 최신순 기본 정렬) → 검색어 입력(REQ-07, 제목·요약·출처명 대상) 또는 출처 탭 선택(REQ-11) → 목록 즉시 재계산 + 페이지 1로 리셋 → 20건 초과 시 페이지네이션 노출(REQ-09/10) → 카드 클릭(REQ-12) → S-02 상세로 이동.
- **a11y**: 카드는 `listRow`와 달리 시각적 박스이지만 클릭 영역은 기존 `post-item`처럼 카드 전체를 감싸는 단일 `<Link>`로 유지 — 카드 내부에 별도 앵커(원문 링크 등) 중첩 금지(목록에서는 원문 링크 노출 안 함, 상세에서만). 출처 필터 탭은 기존 `role="group"` + `aria-selected` 패턴 재사용(신규 tablist 도입 금지 — 기존 코드 일관성 우선). 페이지네이션은 기존과 동일하게 `aria-current="page"` 필수.

## S-02 핫이슈 상세

- **레이아웃**: 기존 글 상세(`.post-head` 구조) 톤을 재사용하되 세리프 큰 제목 대신 font_sans 700 제목(자체 글과 구분 유지). 상단 = 출처 뱃지 + 수집일 + "AI 요약" 라벨 한 줄. 중단 = 제목. 하단 = 요약 본문(body 톤, `tldr`류 강조 없이 일반 문단) → 하단 고정 영역에 원문 링크 버튼(`components.badge` 톤이 아닌 밑줄 링크, 기존 `.refs a` 스타일 재사용: `colors.primary` + underline).
- **상태**:
  - 로딩: 제목 라인 + 요약 문단 3~4줄 스켈레톤.
  - 빈 상태(해당 slug/id의 이슈가 존재하지 않음 — 삭제/오탈자 URL): 기존 `not-found.tsx`와 동일한 패턴으로 "이슈를 찾을 수 없습니다" + 목록으로 돌아가기 링크.
  - 에러(요약 데이터 누락 등 — A-02 연쇄로 요약 없이 원문 링크만 있는 예외 케이스 대비): 요약 영역에 "요약을 생성하지 못했습니다. 원문에서 확인해 주세요." 안내 문구로 대체, 원문 링크는 항상 노출(A-11).
- **흐름**: 목록에서 카드 클릭(REQ-12) → 상세 진입(REQ-13, 요약·출처명·수집일·원문 링크 표시) → 원문 링크 선택 시 새 탭으로 원문 이동(REQ-14, `target="_blank" rel="noopener noreferrer"`).
- **a11y**: 원문 링크는 새 창으로 열리므로 링크 텍스트 또는 `aria-label`에 "새 창에서 원문 열림" 안내 포함. 요약이 매우 길 경우에도 문단 구조(`<p>`)로 스크린리더가 자연스럽게 순회 가능하도록 함(카드처럼 요약 전체를 하나의 인라인 텍스트로 뭉치지 않음).

## 공통 참고

- 신규 색상은 `colors.destructive`(#B3261E / dark #E5867E) 1건만 추가 — 기존 팔레트(paper/ink/sub/faint/marker/pen/line) 확장 없이 그대로 재사용.
- `components.card`는 이번 피처를 위해 신규 추가된 프리셋(기존에는 listRow만 존재) — ui_developer는 hot-issues 전용 카드 컴포넌트에서만 사용하고 기존 `PostItem`(listRow)은 그대로 유지.
- 검색·페이지네이션 로직(정규화·부분일치·5페이지 창 이동)은 `components/PostsFilter.tsx`의 기존 구현 패턴을 그대로 재사용 가능 — 디자인 관점에서 신규 인터랙션 패턴 도입 없음.
