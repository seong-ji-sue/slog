## §0 개요·목적

### 이슈 / AS-IS / TO-BE

| 구분 | 내용 |
|------|------|
| **AS-IS** | 블로그에는 저자가 직접 작성한 글만 존재. 유명 개발·AI 뉴스 출처(Hacker News·GeekNews·Dev.to 등)의 동향을 확인하려면 방문자가 각 사이트를 개별 방문해야 함. |
| **이슈** | 외부 출처를 매번 개별 방문해야 하는 번거로움으로 개발·AI 동향 파악 진입장벽이 높음. 기존 글 목록에는 이런 외부 수집 콘텐츠를 위한 별도 구조가 없음. |
| **TO-BE** | 유명 개발·AI 뉴스 출처의 이슈를 매일 자동으로 수집해 카드 형태로 제공하는 별도 피드 섹션을 신설. 사용자는 외부 사이트 개별 방문 없이 한 곳에서 최신 동향을 훑어보고, 카드 클릭 시 요약된 상세를 확인할 수 있음. |

### 특장점

- 매일 자동 수집으로 최신 동향을 상시 유지 ([F-01][F-02])
- 기존 글 목록의 검색·페이지네이션 UX를 그대로 재사용해 학습비용 최소화 ([F-04][F-05][F-06])
- 요약만 제공하고 원문 링크로 유도해 저작권 부담 최소화 (FACTS ISSUE-005 답변)
- 기존 글 목록과 완전히 분리된 별도 섹션으로 자체 작성 콘텐츠와 외부 수집 콘텐츠를 명확히 구분 (FACTS ISSUE-002 답변)

## §2 화면·상호작용

### H-01 핫이슈 피드 목록 — 신규

**경로**: 상단 내비 '핫이슈' 링크 클릭 또는 핫이슈 피드 경로 직접 진입 — 기존 글 목록과 분리된 별도 라우트(FACTS ISSUE-002 답변). 진입 링크는 기존 상단 내비게이션(B-01 nav-main)에 '핫이슈' 항목을 추가해 제공함.
**상태**: 신규 화면

**영역**

| 영역 | 설명 |
|------|------|
| 검색 입력창 | 제목·요약·출처명 대상 공백 무시 부분일치 검색 ([F-05][A-08]) |
| 출처 필터 탭 | '전체' + 고정 출처(Hacker News·GeekNews·Dev.to) 탭 (FACTS ISSUE-001 답변, [A-09]) |
| 핫이슈 카드 리스트 | 제목·출처명·수집일·요약 스니펫 포함 카드, 수집 시각 최신순 정렬 ([F-03][A-06][A-07]) |
| 결과 없음 안내(검색·출처 필터 0건) | 검색어·출처 필터 적용 결과가 0건일 때(검색어만·출처 필터만·둘 다 적용된 경우 모두 포함) 안내 문구 ([F-06], DESIGN S-01) |
| 필터 초기화 버튼 | 결과 없음 안내와 함께 노출되는 텍스트 버튼. 클릭 시 검색어·출처 필터를 해제해 전체 목록을 복원(DESIGN S-01) |
| 전체 이슈 0건 안내 | 저장된 이슈 자체가 0건(최초 수집 전 등)일 때 안내 문구 — 검색·출처 필터 결과 0건과 별개 상태(DESIGN S-01) |
| 로딩 스켈레톤 | 데이터 로딩 중 카드 형태 스켈레톤 3~5개 표시(DESIGN S-01) |
| 목록 조회 에러 안내 | 목록 조회 실패 시 에러 안내 + 재시도 버튼(DESIGN S-01) |
| 페이지네이션 컨트롤 | 페이지당 20건, 5페이지 단위 이동 ([F-04][A-08]) |

**인터랙션**: 검색어 입력 → 실시간 필터링(제목·요약·출처명, 공백 무시 부분일치) + 페이지네이션 1페이지로 재설정(DESIGN S-01). 출처 탭 클릭 → 해당 출처 카드만 노출, '전체' 클릭 시 복원, 페이지네이션 1페이지로 재설정(DESIGN S-01). 검색어·출처 필터 적용 결과 0건 시 노출된 필터 초기화 버튼 클릭 → 검색어·출처 필터 해제, 전체 목록 복원. 카드 클릭 → 핫이슈 상세(H-02)로 이동. 페이지 번호 선택 → 해당 페이지 카드만 표시; 5페이지 단위 창을 초과하는 페이지 존재 시 다음/이전 페이지 창으로 이동 가능. 재시도 버튼 클릭 → 목록 재조회 시도, 재조회 성공 시 카드 목록 표시.

### H-02 핫이슈 상세 — 신규

**경로**: 핫이슈 피드 목록(H-01)에서 카드 클릭
**상태**: 신규 화면

**영역**

| 영역 | 설명 |
|------|------|
| 제목 | 이슈 제목 표시(DESIGN S-02) |
| 요약 | 원문 내용을 한국어로 요약한 텍스트 ([F-07][A-02][A-03]) |
| 요약 누락 안내 | 요약 생성에 실패한 이슈일 때 요약 영역 대신 표시되는 대체 안내 문구 — '요약을 생성하지 못했습니다. 원문에서 확인해 주세요.'(DESIGN S-02 §상태) |
| 출처명 | 원문 출처명 표시 ([A-11]) |
| 수집일 | 이슈 수집일 표시 ([F-07]) |
| 원문 링크 | 원문 페이지로 이동하는 링크 (FACTS ISSUE-005 답변, [A-11]); 요약 누락 상태에서도 항상 노출됨(DESIGN S-02 §상태) |
| 로딩 스켈레톤 | 데이터 로딩 중 제목 라인 1개 + 요약 문단 3~4줄 형태의 스켈레톤 표시(DESIGN S-02 §상태) |
| 존재하지 않음 안내 | 존재하지 않는 식별자 접근 시 안내 문구 + 목록으로 돌아가기 링크(DESIGN S-02) |

**인터랙션**: 원문 링크 선택 → 원문 페이지가 새 탭에서 열림(DESIGN S-02, 현재 화면 유지). 목록으로 돌아가기 링크 선택(존재하지 않음 안내 상태) → 핫이슈 피드 목록(H-01)으로 이동.

> **[A-11] 편차 안내**: [A-11]은 "상세 페이지와 카드에는 원문 출처명과 원문 링크를 항상 함께 표기"를 가정했으나, DESIGN S-01 §a11y 근거(카드 전체를 감싼 단일 `<Link>` 내부에 원문 링크를 중첩하면 앵커 중첩(`a > a`) 접근성 오류가 발생함)에 따라 카드(H-01)에는 원문 링크를 표기하지 않고 상세(H-02)에서만 노출하는 것으로 의도적으로 편차를 둠. 카드에는 출처명만 표기하고, 원문 링크는 카드 클릭 후 진입하는 상세 화면에서만 제공함.

## §8 impl_requirements

### FE

1. 화면 H-01(핫이슈 피드 목록)은 검색 입력창, 출처별 필터 탭(전체+고정 출처), 핫이슈 카드 리스트(제목·출처명·수집일·요약 스니펫 포함), 결과 없음 안내 문구, 필터 초기화 버튼, 페이지네이션 컨트롤(페이지당 20건, 5페이지 단위 이동)을 제공해야 한다; 데이터 로딩 중에는 카드 형태 스켈레톤을, 저장된 이슈가 0건일 때는 검색·출처 필터 결과 0건 안내와 구분되는 전체 이슈 0건 안내를, 목록 조회 실패 시에는 에러 안내와 재시도 버튼을 제공해야 한다.
2. 검색은 제목·요약·출처명 텍스트에 대해 공백을 무시한 부분일치로 필터링해야 하며, 검색어·출처 필터 적용 결과가 0건이면 결과 없음 안내 문구와 필터 초기화 버튼을 함께 표시해야 한다; 필터 초기화 버튼 클릭 시 검색어를 비우고 출처 필터를 '전체'로 되돌려 전체 목록을 복원해야 한다.
3. 카드 목록은 수집 시각 최신순으로 정렬돼야 하며, 카드 클릭 시 해당 이슈의 상세 화면(H-02)으로 이동해야 한다.
4. 목록 조회 실패 후 재시도 버튼 클릭 시 목록을 재조회해야 하며, 재조회가 성공하면 에러 안내 대신 카드 목록을 표시해야 한다.
5. 화면 H-02(핫이슈 상세)는 제목·요약·출처명·수집일·원문 링크를 제공해야 한다; 원문 링크 선택 시 원문 페이지가 새 탭에서 열려야 한다(현재 화면 유지); 존재하지 않는 식별자로 접근 시 이슈를 찾을 수 없다는 안내와 목록으로 돌아가기 링크를 제공해야 한다.
6. 화면 H-02(핫이슈 상세)는 데이터 로딩 중 제목 라인 1개와 요약 문단 3~4줄 형태의 스켈레톤을 표시해야 하며, 해당 이슈의 요약 데이터가 없는 경우 요약 영역 대신 '요약을 생성하지 못했습니다. 원문에서 확인해 주세요.' 안내 문구를 표시하되 원문 링크는 이 상태에서도 항상 함께 노출해야 한다.
7. 핫이슈 피드는 상단 내비게이션의 '핫이슈' 링크를 통해 진입 가능한, 기존 글 목록과 분리된 별도 진입 경로로 제공해야 하며, 기존 글 목록 화면 동작에는 영향을 주지 않아야 한다.
8. 검색어 입력 또는 출처 탭 변경 시 핫이슈 목록의 페이지네이션은 1페이지로 재설정돼야 한다.
9. 핫이슈 카드(H-01)에는 원문 링크를 표기하지 않고 출처명만 표기해야 한다; 원문 링크는 상세 화면(H-02)에서만 제공해야 한다([BR-HOT-20], DESIGN S-01 §a11y — 카드 전체를 감싼 단일 링크 내부에 원문 링크를 중첩할 경우 발생하는 앵커 중첩 접근성 오류 회피).

### BE

1. 핫이슈 수집 배치는 매일 1회 지정된 시각에 실행되어 고정된 출처 목록(Hacker News·GeekNews·Dev.to 등)에서 신규 이슈를 수집·저장하는 계약을 제공해야 한다.
2. 신규 이슈 수집 시 원문 내용을 요약해 한국어로 함께 저장하는 계약을 제공해야 한다; 요약은 수집 시점에 1회만 생성되고 이후 조회 시 재생성하지 않아야 한다; 요약 생성에 실패한 경우 요약 필드를 비운 채로 저장하고 나머지 필드(제목·출처·수집일·원문 URL)는 정상 저장하는 계약을 제공해야 한다.
3. 이슈 중복 판정은 원문 URL 동일 여부로 수행해야 하며, 이미 저장된 URL이 재수집되면 중복 저장하지 않고 기존 항목을 유지하는 계약을 제공해야 한다.
4. 특정 출처의 수집이 실패해도 나머지 출처의 수집은 계속 진행돼야 하며, 원문 접근에 실패한 이슈는 목록 노출 대상에서 제외해야 한다.
5. 특정 수집 주기에 신규 이슈가 없으면 기존 저장 목록을 그대로 유지하는 계약을 제공해야 한다.
6. 핫이슈 목록 조회는 `{id, title, source, summarySnippet, collectedAt}` 필드를 포함하는 목록을 검색어·출처·페이지 파라미터로 필터링해 반환하는 계약을 제공해야 한다.
7. 핫이슈 상세 조회는 `{id, title, source, summary, collectedAt, originalUrl}` 필드를 포함하는 단일 항목을 반환하는 계약을 제공해야 한다; `summary`는 요약 생성 실패 시 비어있을 수 있는(nullable) 필드여야 한다.
8. 수집된 이슈는 삭제 로직 없이 무기한 누적 보관하는 저장 계약을 제공해야 한다.
