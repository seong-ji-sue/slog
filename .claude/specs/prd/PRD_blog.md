**feature**: blog

## §0 개요·목적

### 이슈 / AS-IS / TO-BE

| 구분 | 내용 |
|------|------|
| **AS-IS** | P2 5화면(홈·글목록·글상세·시리즈·소개) 구현·배포 완료. P4 태그 인덱스·상세는 feature/tags-page 브랜치에 구현, v2-pivot-spec에 미병합 상태. project taxonomy 없음. |
| **이슈** | (1) 태그 328개를 탐색할 화면이 없음. (2) 태그 관계를 시각적으로 파악할 수 없음. (3) 글이 어느 프로젝트(개인/회사)에 속하는지 taxonomy가 없어 콘텐츠 분류·AI 서칭 기반 미비. |
| **TO-BE** | feature/tags-page 브랜치 병합 후 /tags 목록·그래프 뷰 토글과 /tags/[tag] 상세를 추가함. project frontmatter 7종을 신설하고 포스트 카드·글 상세 메타에 배지로 표시함. |

### 특장점 (PLAN.md §1·§11 근거)

- `LOG_NNN` 시리얼 번호·형광펜 mark·볼펜 블루 카테고리 — 티스토리 습관을 디자인 시스템으로 승격
- 태그 co-occurrence 그래프로 지식 구조 시각화 (PLAN.md §11-4)
- project taxonomy 7종으로 개인/회사 작업 분류 — 향후 RAG 서칭 기반 (PLAN.md §11-2·§11-6)
- 회사 프로젝트 콘텐츠는 식별정보 마스킹 정책 적용 (PLAN.md §11-3)

## §2 화면·상호작용

### B-01 홈(Home) — 수정

**경로**: 사이트 루트 진입
**상태**: 기존 구현 화면. project 배지 추가(수정)

**영역**

| 영역 | 설명 |
|------|------|
| 사이트 헤더 | 로고(`SLOG_`) + 내비게이션 메뉴(글·시리즈·소개·RSS) + 다크모드 토글 |
| 히어로 | Noto Serif KR 900 제목(`무엇이 될지 모르는 평범한 개발자의 기록`) + 소개 2줄 bio + 통계 라인 |
| 피처드(고정 3편) | 포스트 카드 포맷, 운영자 선정 3편 고정 노출 |
| 전체 글 피드 | 최신순 포스트 카드 리스트. **[수정]** 카드에 project 배지 추가(project 필드 있는 글만) |
| 사이트 푸터 | 저작권 + GitHub·RSS·Tistory 아카이브 링크 |

**포스트 카드 구성** (PLAN.md §4 목업 관측):
`LOG_NNN · 카테고리` + 제목(mark 스윕 hover) + 설명 + `날짜 · 난이도 ★ · 읽기 시간` + **project 배지(있는 경우)**

## §8 impl_requirements

### FE

1. 화면 B-01(홈)은 사이트 헤더(로고+내비+다크모드 토글), 히어로 영역(Noto Serif 900 제목+bio 2줄+통계 라인), 피처드 3편 고정 카드 블록, 최신순 포스트 카드 피드, 푸터를 제공해야 한다.
2. 포스트 카드는 LOG 번호, 카테고리(볼펜 블루 색상), 제목(mark 포함 가능), 설명, 날짜·난이도·읽기 시간 메타 정보를 표시해야 한다. project 필드가 있는 경우 project 배지를 추가로 표시해야 하며, project 필드가 없는 포스트는 project 배지를 표시하지 않아야 한다.
3. 포스트 카드 hover 시 제목 형광펜이 background-size 0% → 100% 스윕 전환으로 나타나야 한다; prefers-reduced-motion 활성 시 transition을 제거해야 한다.
4. 다크모드 토글은 클릭 시 전체 페이지 팔레트를 다크 모드로 전환해야 하며, 라이트 상태를 기본으로 유지해야 한다.
5. 화면 B-02(/posts)는 카테고리 필터 버튼 그룹과 전체 글 카드 리스트를 제공해야 한다; 필터 선택 시 해당 카테고리 글만 노출하고, '전체' 선택 시 전체 글을 복원해야 한다.
6. 화면 B-03(글 상세)은 포스트 헤더(LOG·카테고리·날짜·난이도), Noto Serif 900 h1 제목, TL;DR 블록, 키워드 프리뷰 칩 목록, 본문(✅ 헤딩·대화체 인용·코드 블록·mark), 참고한 링크 섹션, 시리즈 내비 카드를 제공해야 한다. project 필드가 있는 글의 포스트 헤더 메타 영역에는 project 배지를 표시해야 하며, project 필드가 없는 글은 project 배지를 표시하지 않아야 한다.
7. 본문 최대폭은 680px 고정이어야 한다.
8. 코드 블록은 #1D1D22 배경의 다크 아일랜드 스타일을 적용해야 하며, 라이트 모드·다크 모드 무관하게 어두운 배경을 유지해야 한다.
9. 화면 B-04(/series)는 시리즈 카드 목록을 제공해야 하고, 시리즈 카드 선택 시 순서 번호가 포함된 해당 시리즈 글 목록을 표시해야 한다.
10. 화면 B-05(/about)는 이력 요약·기술 스택·프로젝트 링크·연락처 4개 영역을 구조로 제공해야 한다; 프로젝트 링크는 외부 URL을 새 탭으로 열어야 한다.
11. 키보드 포커스 시 해당 요소에 형광펜 표시가 나타나야 한다(접근성).
12. 폰트는 Noto Serif KR 900(제목), Pretendard(본문), JetBrains Mono(메타·코드·로고)를 구분해 적용해야 한다.
13. 화면 B-06(/tags)은 목록 뷰/그래프 뷰 전환 토글, 태그 목록(목록 뷰; 태그명+글 수), 태그 co-occurrence 그래프(그래프 뷰; 노드=태그·엣지=동일 글에 공존한 태그 쌍)를 제공해야 한다; 기본값은 목록 뷰이며, 고립 태그(co-occurrence 엣지가 없는 태그)는 그래프에서 제외해야 한다.
14. 화면 B-07(/tags/[tag])은 태그 제목('#[태그명]')과 해당 태그가 포함된 포스트 카드 목록을 제공해야 한다.

### BE

1. 글 목록 조회는 `{slug, lognum, title, description, category, date, difficulty, readingTime, project}` 필드를 포함하는 목록을 반환하는 계약을 제공해야 한다; project는 nullable이어야 한다.
2. 글 상세 조회는 `{slug, lognum, title, description, category, date, difficulty, readingTime, tldr, keywords, body, seriesPrev, seriesNext, refs, project}` 필드를 포함하는 단일 항목을 반환하는 계약을 제공해야 한다; project는 nullable이어야 한다.
3. 시리즈 목록 조회는 `{seriesId, title, postCount, lastUpdated}` 목록을 반환하는 계약을 제공해야 한다.
4. 시리즈 상세 조회는 해당 시리즈에 속한 글 목록을 순서 번호(order)를 포함하여 반환하는 계약을 제공해야 한다.
5. 카테고리 필터 조회는 카테고리 값을 파라미터로 받아 해당 카테고리 글 목록만 반환하는 계약을 제공해야 한다.
6. 태그 목록 조회는 `{tag, postCount}` 목록을 반환하는 계약을 제공해야 한다.
7. 태그별 포스트 조회는 tag 식별자를 파라미터로 받아 해당 태그가 포함된 포스트 목록을 반환하는 계약을 제공해야 한다.
8. 태그 co-occurrence 조회는 `{source, target, weight}` 엣지 목록을 반환하는 계약을 제공해야 한다; weight는 두 태그가 함께 쓰인 포스트 수이며, 고립 태그(엣지 수=0)는 결과에서 제외해야 한다.
